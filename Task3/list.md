# Список требований, которым должны удовлетворить внешние интеграции

## Требования к безопасности

1. Подключение к внешним интеграциям через IPSec
2. Внутри ipsec используется RESTful API и/или WS защищенные TLS (для уменьшения вероятности перехвата трафика при проникновение через периметр поставщика)
3. Ограничение доступа поставщика к API компании
4. Все сообщения передаваемые через внешние интеграции должны логироваться
5. Проверять перед подключением поставщика, что он соответствует стандартам и законодательным требованиям, включая 152-ФЗ
6. Все внешние интеграции должны быть под постоянным мониторингом, обеспечивающим автоматические оповещения о инцидентах.

## Протоколы аутентификации и авторизации

Аутентификации и авторизации по средством OpenID Connect и OAuth 2.0

## Требования к взаимодействию между системами предприятия и внешними платформами

1. Инициация подключения к внешним поставщикам происходит на стороне компании
2. На случай недоступности поставщика должен быть реализован circuit breaker
3. Поставщик должен передавать версию своего api по фиксированному и не изменяемому url, должен быть мониторинг изменений версий api поставщика.
